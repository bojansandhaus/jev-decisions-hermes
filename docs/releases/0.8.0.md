# Jev Decisions 0.8.0

This release implements the shared four mode provider contract and turns the local `laya` provider into a **generic local decision model slot** that any local System One decision model can occupy. Both changes are additive: every mode name, every alias and every test that existed in 0.7.0 behaves as it did, and the default is still `openrouter` sending the same request it always sent.

## Added

### The four canonical modes

Four names now cover every arrangement. Each says which side leads and whether the other side is a fallback, and none of them names a particular provider:

| Mode | Leads | Fallback | Order under an OpenRouter credential |
|---|---|---|---|
| `api_with_local_fallback` | hosted API | local slot | `openrouter`, then `laya` |
| `api_only` | hosted API | none | `openrouter` |
| `local_only` | local slot | none | `laya` |
| `local_with_api_fallback` | local slot | hosted API | `laya`, `openrouter`, `typesafe` |

`api_only` and `local_only` are single provider routes: one hop, no fallback, no chain, and a failure is reported rather than rerouted. The other two are two provider chains and use the existing cooldown, trigger and breaker machinery unchanged.

**The hosted side is chosen by configuration, not by the mode.** `api_only` and `api_with_local_fallback` resolve it by credential: OpenRouter when `OPENROUTER_API_KEY` is present, direct TypeSafe when `TYPESAFE_API_KEY` is, and Clef when `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` are. A Cloudflare token without an account id does not select Clef, because that pair cannot route anywhere. With no hosted credential present the repository's default provider is named, so the missing key is reported by the existing selection check rather than by an invented mode.

### The mirror chains: hosted first, local behind them

`api_with_local_fallback` needs routes this repository did not have: a hosted provider **leading** with the local slot behind it. Three new modes provide them.

| Mode | Order |
|---|---|
| `typesafe_then_laya` | `typesafe`, `laya` |
| `openrouter_then_laya` | `openrouter`, `laya` |
| `clef_then_laya` | `clef`, `laya` |

This required widening `validate_fallback_order`, which until now refused `laya` in any position other than first on the grounds that "Laya is a local provider, not a hosted Jev provider, so it cannot follow a hosted hop". Laya may now lead a chain or **trail** one; it may still not sit between two hosted hops, and `("laya",)` on its own is still refused because the plain local mode is selected by its own name.

The privacy consequence is the reverse of `laya_then_*`, and the docs say so plainly. A `laya_then_*` mode keeps the case state home while the local server answers and only sends it out when the local server fails. A `<hosted>_then_laya` mode goes to the hosted API first and uses the local server only when that route is unavailable.

`uses_local_hop` now returns true whenever a chain *contains* the local slot rather than only when it leads it, so a hosted first chain that falls through to a local server on CPU waits the full local budget instead of the hosted 30 seconds.

### `JEV_LOCAL_MODEL`: the local slot is a slot, not a binding

The provider name in configuration stays `laya`. What changes is that it now selects a **slot**, and a new setting chooses which local model answers inside it:

```
JEV_LOCAL_MODEL=<engine or checkpoint name>   # default: english
```

There is deliberately **no allowlist of model names**. The whole point is interchangeability: an engine nobody has heard of must work with no code change and no new provider name. What is refused instead is only what would corrupt the request, because the name is interpolated into a JSON string and may become a URL path segment:

- an empty or whitespace-only value, which is reported rather than silently treated as the default, and
- a value carrying a quote, backslash, control character, `/`, `?`, `#`, `%`, or anything else in that class.

A rejection names the setting and the reason, never echoes the value back, and happens before any socket is opened.

**`JEV_LAYA_MODEL` is kept and still works.** It is the name this setting had before the slot became generic. When both are set, `JEV_LOCAL_MODEL` wins, because it is the name that is not tied to one model.

**The default request is unchanged.** `JEV_LOCAL_MODEL` defaults to `english`, which is the checkpoint `laya-serve` serves by default and the only one this repository has ever called. This is the one place where a literal reading of "defaults to `laya`" would have broken the backwards compatibility requirement, so the deviation is deliberate and stated: `laya` is the default *slot*, and `english` is the default *engine in that slot*. A default configuration sends byte for byte the request it always sent.

Local models known to fit the same `/v1/systemone` contract: `laya` (plus its `multilingual` and `typed-decisions` engine names), `kev` (also `kev-0.8b`), `tev1` (Together AI's open-weight Qwen3.5-based System One decision model, `Tev1-4B` and `Tev1-0.8B`, at [togethercomputer/tev1](https://github.com/togethercomputer/tev1)), and `jeff-qwen3.5-0.8b` and `jeff-gemma4-e2b`.

The interchangeability claim is sourced rather than asserted. [chaitin/Decis](https://github.com/chaitin/Decis) is a self hosted server publishing this same Jev compatible `/v1/systemone` endpoint and serving more than one engine, one Docker image per engine, where repointing `base_url` is the whole migration. `docs/integrations.md` carries a worked example of pointing the slot at it.

### Three more aliases, and `jev_api` accepted at last

| Alias | Resolves to | Order |
|---|---|---|
| `jev_api` | `api_only` | by credential |
| `clef_with_local_fallback` | `api_with_local_fallback` | `clef`, `laya` |
| `laya_then_hosted` | `local_with_api_fallback` | `laya`, `openrouter`, `typesafe` |

`jev_api` was **refused** before this release: the reference documentation said the hosted Jev arrangement it names "already has four explicit mode names here". It now resolves to `api_only` with the hosted side chosen by credential, which is what the name always meant. To pin DOGA's OpenRouter-first two-provider order instead, use `openrouter_then_typesafe`.

The three pre-existing aliases (`clef_api`, `laya_local`, `laya_with_jev_fallback`) keep their exact mappings. Every alias resolves to a canonical mode before anything routes, so no alias string reaches a chain, a diagnostic, a log line, or a URL. `resolve_mode` stays case insensitive and still fails closed on an unknown name with an error listing every accepted value; there are now thirteen concrete modes, four canonical modes and six aliases, so `JEV_PROVIDER_MODE` accepts twenty-three names.

## Changed

### Reuse, not a parallel code path

Clef can now be a hop inside a chain rather than a whole route, so two helpers were generalised rather than duplicated:

- **`_transport_once` and `_request_once` recognise a Clef endpoint from its shape** and apply Clef's question id mapping and envelope reader there. A Clef hop inside `clef_then_laya` therefore behaves exactly as Clef does alone, including mapping `candidate:aaa` out and the caller's own ids back in. Both keep their existing signatures, so every existing test double that monkeypatches them still works.
- **`_with_routing` now keys on `FALLBACK_MODES`** rather than `LAYA_CHAIN_MODES`, so a hosted first chain reports its routing block too. Single provider modes still return the provider's own response with no such block, unchanged.

### Documentation

`README.md`, `docs/reference.md`, `docs/integrations.md`, `docs/approvals.md` and `.env.example` describe the mode table, the `JEV_LOCAL_MODEL` setting, the alias table and the interchangeability claim with its source. `docs/reference.md` gains three sections: [the four canonical modes](reference.md#the-four-canonical-modes), [mode aliases](reference.md#mode-aliases) and [the local slot is a slot, not a model](reference.md#the-local-slot-is-a-slot-not-a-model). `docs/integrations.md` gains [pointing the local slot at a different engine](integrations.md#pointing-the-local-slot-at-a-different-engine), with the `chaitin/Decis` example.

Every statement that Clef or the local slot has "no fallback" was qualified rather than deleted, because `clef_then_laya` makes the unqualified claim false.

The category vocabulary was also aligned across the same documents. Where the documentation previously described the local engines as "Jev-like models" it now says **System One decision model**, with a link to [the category definition](https://systemonemodels.org/guides/what-is-a-system-one-model/), because Jev is one vendor's member of the category rather than the category itself. `README.md` lists the members and carries a new **Repository topics** subsection naming the 18 topics this repository holds, why `human-in-the-loop`, `agent-architecture` and `llm` were removed to stay under GitHub's 20 topic cap, and that they should not be restored.

Other members catalogued in the same index: **CLM** and **GLiNER2.5-Decide** (open weights), plus hosted **d1** (Liquid AI), **Mercury Decide** (Inception, free on OpenRouter), **Solar Decide** (Upstage), **pplx-decider** (Perplexity), **Span-01** (Respan), **Decider 1** (meraGPT), and the **OpenAI Decisions API**.

## Backwards compatibility

A configuration that worked in 0.7.0 produces the same routing decision in 0.8.0. No setting was removed and no setting silently changed meaning. A test asserts every pre-existing mode keeps its exact provider order, and a test asserts each alias behaves identically to the mode it names, comparing both the result and the hop sequence.

**Two existing assertions were updated because this change intentionally alters the behaviour they encoded**, and only those two:

1. `test_the_local_route_is_rejected_as_a_fallback_member` asserted that `("typesafe", "laya")` raises, on the grounds that Laya "cannot follow a hosted hop". `api_with_local_fallback` requires exactly that shape, so the assertion is now `test_the_local_slot_may_lead_a_chain_and_may_trail_one`: trailing is accepted, the sandwich case still raises, and the error message changed to match.
2. `test_laya_may_lead_a_chain_but_never_follow_a_hosted_provider` asserted the same rule a second time and was **merged into the test above** rather than kept as a near duplicate. Its remaining assertions (duplicate providers refused, a bare `laya` chain refused) are preserved there.

Two smaller edits were needed for the same reason: `test_only_the_modes_that_name_laya_include_it` now keys on `FALLBACK_MODES` because the hosted first chains also name Laya, and `test_the_doga_aliases_resolve_to_the_modes_documented_for_them` now resolves an alias that names a canonical mode one step further, since that is what the resolution does.

No test was deleted to make the suite pass.

## Privacy and failure behaviour

The hosted first chains are the only new egress path, and they run in the opposite direction to the local first ones: the case state goes to the hosted API on the first attempt and reaches a local server only when that attempt fails. Everything else is unchanged. `api_only` and `local_only` still never reroute a failure.

Log hygiene matches the 0.6.1 guarantee. A failure logs only the provider name and the exception class, never the reviewed state, never the credential, never an answer. New tests assert this for both a local fallback chain and a hosted only route, and assert that a refused `JEV_LOCAL_MODEL` never echoes its own value into the message.

The three consecutive local failure breaker is unchanged and still bounds only a **local first** chain, because that is the only direction in which a local failure becomes egress to a hosted provider. A local failure in `openrouter_then_laya` leaves the count alone; there is no hosted hop to reach and nothing to suppress.

## What was verified, and what was not

**No live call was made to any provider, and none was possible.** No credential on this machine is authorized for Cloudflare Workers AI (every candidate returns HTTP 401 from `api.cloudflare.com`), no hosted Jev key is available to a test process, and no local decision server is running. **No local model other than the default `english` checkpoint has ever been called by this repository, and this release does not claim otherwise.** Every new test drives an injected transport or a captured socket and asserts the route, the request shape and the validation, never a live answer.

What the 82 new tests establish:

| Behaviour | How it is proved |
|---|---|
| Each of the four canonical modes' provider order | the resolved order asserted under a controlled environment |
| `api_only` and `local_only` never reroute | `_request_once` is driven to fail and the hop list asserted to hold exactly one entry |
| `api_with_local_fallback` falls through to the local slot | a hosted failure followed by a local answer, with the routing block asserted |
| `local_with_api_fallback` is the mirror | a local failure followed by a hosted answer |
| The hosted side follows the credential | five credential contexts, each asserting its order |
| Clef needs both its variables to be selected | a token without an account id does not select Clef |
| `clef_then_laya` routes through Clef then locally | both hops asserted, including the envelope and id round trip |
| Every alias maps to its canonical mode and order | one parametrised case per alias, plus a hop-by-hop identity comparison |
| No alias string leaks | the resolved mode asserted to be a provider name and not itself an alias |
| `local_model` selects the engine with no allowlist | thirteen engine names accepted, including one nobody has heard of |
| `local_model` changes what the request asks for | the `model` field asserted from a captured hop |
| The default request is unchanged | the default asserted equal to `LAYA_MODEL_DEFAULT` |
| `JEV_LAYA_MODEL` still works, and loses to `JEV_LOCAL_MODEL` | both spellings asserted alone and together |
| An empty or whitespace `local_model` is refused | five blank variants, plus non-string values |
| A corrupting `local_model` is refused | ten cases, each with the specific characters that would break a URL or a JSON string |
| A refused `local_model` never reaches a socket | `urlopen` replaced by a fixture that fails the test if called |
| A refusal never echoes its value | the value asserted absent from the error message |
| No log carries state, answers or a credential | captured logs asserted to contain the class and none of the fixture content |
| The default mode did not move | asserted `openrouter` |

What remains unverified, plainly:

1. **No local model other than the default `english` checkpoint has been called.** The claim that `kev`, `tev1` or a `jeff` engine fits this slot rests on the shared `/v1/systemone` contract and on [chaitin/Decis](https://github.com/chaitin/Decis) serving those engines behind that endpoint, not on this repository having called one. A first run against a real non default engine should be checked before being relied on.
2. **Judgement quality of any engine in the slot is unmeasured.** The 0.5.0 measured limits of the base checkpoint apply to whatever engine you select. Calibrate on your own labelled examples first.
3. **The three hosted first chains have no live run behind them.** They are proved by injected transports and captured sockets only, exactly as the Clef route was in 0.7.0.
4. **`api_only` and `api_with_local_fallback` have no default hosted provider of their own.** With no hosted credential present they name `openrouter` and then fail at selection naming `OPENROUTER_API_KEY`, which is the honest failure but is a failure rather than a default. This is deliberate: imposing a hosted preference would contradict the contract that the hosted side is chosen by configuration.
