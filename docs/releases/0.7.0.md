# 0.7.0, live enforcement

Jev Decisions 0.7.0 adds an operational boundary instead of another observer layer.

## What is live

The new `jev_live` tool exposes four bounded actions:

- `authorize_action`: returns `allow`, `ask`, or `deny` for a prospective state changing action.
- `gate_memory`: returns `retain`, `hold`, or `discard` before durable memory writes.
- `triage_anomaly`: returns `ignore`, `inspect`, `escalate`, or `hold` for operational anomalies.
- `verify_action`: requires explicit change, readback, and evidence fields after an action.

Each decision writes a local hashed receipt to the existing Jev ledger. Raw candidate text, arguments, and provider state are not written into the receipt.

## Automatic action gating

Set both variables in the Hermes process to gate mutating tool calls before execution:

```bash
JEV_ENABLE_HOOKS=1 JEV_LIVE_ENFORCEMENT=1 hermes
```

Read only calls bypass the provider. Mutating calls fail closed when the provider is unavailable or returns uncertainty. Existing deterministic Hermes approval remains authoritative, and the plugin never executes a tool itself.

## Boundary

Jev supplies a typed semantic judgment. The plugin applies thresholds and deterministic policy. Hermes remains responsible for credentials, tool execution, user confirmation, retries, and external side effects.

This release does not add shadow records as a substitute for action. The old observer hooks remain available for installations that explicitly want them, but the live path is the recommended path when a workflow must actually stop, retain, escalate, or verify.
